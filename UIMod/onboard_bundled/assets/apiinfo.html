SSUI HTTP API Reference

Need explanations, examples, and setup guides? READ THE ACTUAL DOCUMENTATION HERE Yes, this is the big “read the docs, you magnificent server gremlin” button.

This page is the quick route index for the HTTP interface exposed by SSUI v5. It reflects the routes registered by the current backend; request and response details belong in the wiki.

Authentication: when authentication is enabled, protected routes require the AuthToken JWT cookie returned by POST /auth/login. Routes below are protected unless explicitly described as public.

Request & Response Examples

Examples show successful responses. Error responses generally use an error or status/message object with an appropriate HTTP status.

Authentication

POST/auth/loginCreate an AuthToken cookie
Public endpoint. Save the response cookie and send it with protected requests.

Request JSON

{
  "username": "admin",
  "password": "change-me"
}

200 Response

Set-Cookie: AuthToken=<jwt>; Path=/; Secure; HttpOnly

{
  "token": "<jwt>"
}
curl -k -c cookies.txt -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"change-me"}' https://localhost:8443/auth/login
POST/api/v2/auth/adduserAdd or update a user
The setup registration endpoint /api/v2/auth/setup/register uses the same payload and response.

Request JSON

{
  "username": "operator",
  "password": "another-good-password"
}

201 Response

{
  "message": "User registered successfully",
  "username": "operator"
}
GET/POST/api/v2/auth/setup/apikeyCreate an API identity
GET creates a one-month key. POST requires a positive durationMonths. SSUI currently reads JWTs from the AuthToken cookie.

POST Request JSON

{
  "durationMonths": 6
}

201 Response

{
  "message": "APIKey registered successfully",
  "apikey": "<jwt>",
  "expires": "2027-02-28T12:00:00Z"
}
POST/api/v2/auth/setup/finalizeFinish first-time setup
No request body. At least one user must already exist. The backend reloads after responding.

200 Response

{
  "message": "Setup finalized successfully",
  "restart_hint": "You will be redirected to the login page..."
}

Configuration & Administration

POST/api/v2/saveconfigPartially update configuration
Only supplied fields are changed. Field names and casing match config.json; never send stored password hashes unless you intentionally mean to replace them.

Request JSON

{
  "ServerName": "Europa Research Base",
  "ServerMaxPlayers": "10",
  "AutoSave": true,
  "SaveInterval": "300",
  "IsStationeersLaunchPadEnabled": true
}

200 Response

{
  "status": "success",
  "message": "Configuration updated successfully"
}
/saveconfigasjson is the legacy form equivalent. Send the same field names as application/x-www-form-urlencoded; success redirects to /config with HTTP 303.
POST/api/v2/advertiser/overrideChange the advertised address
mode is disabled, auto, ipv4, or dns. value is required for IPv4/DNS. SSUI restarts after accepting the change.

Request JSON

{
  "mode": "dns",
  "value": "stationeers.example.com"
}

202 Response

{
  "status": "restarting",
  "message": "Advertiser configuration saved. SSUI is restarting."
}
POST/api/v2/tls/certificateUpload a certificate and private key
Multipart fields are named certificate and privateKey. The pair must match; encrypted keys are unsupported. Maximum request size is 4 MiB.
curl -k -b cookies.txt \
  -F "certificate=@fullchain.pem" \
  -F "privateKey=@privkey.pem" \
  https://localhost:8443/api/v2/tls/certificate

202 Response

{
  "status": "restarting",
  "message": "TLS certificate saved. SSUI is restarting."
}

Backups, Commands & Updates

POST/api/v2/backups/downloadDownload one backup

Request JSON

{
  "index": 3
}

200 Response

Content-Type: application/octet-stream
Content-Disposition: attachment; filename="backup.zip"

<binary backup data>
POST/api/v2/SSCM/runSend a command to the game server
Requires SSCM to be enabled.

Request JSON

{
  "command": "status"
}

200 Response

{
  "status": "success",
  "message": "Command passed to server"
}
POST/api/v2/update/triggerCheck for or apply an SSUI update
Use false for a synchronous check and true to apply an available update in the background.

Request JSON

{
  "allowUpdate": false
}

200 Response

{
  "status": "success",
  "updateAvailable": "true",
  "version": "5.x.x",
  "message": "Update to 5.x.x available"
}

SLP & Workshop Mods

POST/api/v2/slp/uploadUpload a modpkg ZIP
The body is the ZIP itself, not multipart form data.
curl -k -b cookies.txt -H "Content-Type: application/zip" \
  --data-binary @MyModPackage.zip https://localhost:8443/api/v2/slp/upload

200 Response

{
  "success": true,
  "message": "Mod package uploaded and extracted successfully"
}
POST/api/v2/steamcmd/updatemodInstall or update Workshop items
Accepts numeric Workshop IDs or full Workshop URLs. Use workshopHandle for one item or workshopHandles for a batch.

Request JSON

{
  "workshopHandles": [
    "3755414853",
    "https://steamcommunity.com/sharedfiles/filedetails/?id=1234567890"
  ]
}

200 Response

{
  "success": true,
  "message": "Workshop mods downloaded successfully",
  "logs": ["..."]
}

Custom Detections

POST/api/v2/custom-detectionsCreate a detection rule
type must be keyword or regex. The server generates id and defaults eventType to CUSTOM_DETECTION when omitted.

Request JSON

{
  "type": "keyword",
  "pattern": "Pressure Critical",
  "eventType": "BASE_ALERT",
  "message": "A pressure alarm was detected"
}

201 Response

{
  "id": "9e59cfa7-4ccb-4f2e-8af0-59a38bb7e294",
  "type": "keyword",
  "pattern": "Pressure Critical",
  "eventType": "BASE_ALERT",
  "message": "A pressure alarm was detected"
}
DELETE/api/v2/custom-detections/delete/?id=UUIDDelete a detection rule
No request body. A successful deletion returns HTTP 204 No Content.
